## 2. 整体系统架构设计

### 2.1 六层分层架构

- **Layer 1 前端表现层**：Vue 3.4 + Vite 5 + Element Plus 2.7 + ECharts 5.5；14个页面；护眼深色主题；EMV信号诊断10层过滤漏斗可视化
- **Layer 2 API网关层**：FastAPI 中间件链（CORS -> GZip -> 鉴权 -> 全局异常处理）；统一响应格式 {code,message,data}；JWT Bearer鉴权
- **Layer 3 业务服务层**：
  - 策略引擎 StrategyEngine（fetch_klines -> score -> risk -> order -> close 闭环）
  - 评分引擎 StrategyScoringEngine（技术40% + 新闻30% + AI30% -> 10分制）
  - EMV V7 信号生成器 EMVSignalGenerator（10层过滤漏斗）
  - 交易所适配层 ExchangeAdapter（Binance/OKX 统一抽象，REST+代理+测试网切换）
  - 风控引擎（TP/SL/单笔回撤/日亏/连亏/冷却/间隔）
  - 新闻流水线 NewsPipeline（并发抓取+去重+VADER情绪打标+入库）
  - AIClient 统一封装（火山/百炼/OpenAI/本地 + Mock模式 + Audit记录）
- **Layer 4 数据访问层**：SQLAlchemy 2.0 ORM；9张主表 + 1张ai_configs单例；Alembic迁移预留
- **Layer 5 数据存储层**：MySQL 5.7+/8.0 生产强制；Redis 6+ 队列+缓存；SQLite 离线演示 fallback（自动降级）
- **Layer 6 外部接口层**：币安期货API / OKX API / FRED / EIA / Alpha Vantage / NewsData.io / CoinDesk RSS

### 2.2 核心技术选型说明
| 层 | 选型 | 选型理由 |
|---|---|---|
| 后端框架 | FastAPI 0.111 | 异步原生 / 自动OpenAPI文档 / Pydantic校验 / 性能接近Go |
| ORM | SQLAlchemy 2.0 | 类型安全 / Alembic迁移 / 多引擎兼容（MySQL+SQLite） |
| 缓存+队列 | Redis 6+ + Celery 5.4 | 轻量级分布式队列 / 新闻评分异步执行 / 会话缓存 |
| 前端框架 | Vue 3.4 + Vite 5 | 组合式API / Pinia状态 / 5173热更新快 / 打包体积小 |
| UI组件库 | Element Plus 2.7 | 金融后台友好 / 表格+表单完善 / 深色主题内置 |
| 图表库 | ECharts 5.5 + vue-echarts | 国内项目标配 / 金融图表（K线、热力图、散点）强 |
| AI接口 | 自研 AIClient 统一封装 | 火山方舟/百炼/OpenAI/本地模型 四合一 / Mock模式 / Audit记录 |

| 部署 | 宝塔面板 + Nginx + Supervisor | 运维门槛最低 / WordPress式一键解压即用 |

### 2.3 核心数据流转（一笔EMV策略交易的生命周期）
1. 用户创建策略（run_mode=SIMULATE/AUTO），手动或定时触发 run()
2. StrategyEngine.fetch_klines() 从币安/OKX 拉取200+根4H K线
3. StrategyScoringEngine.score() 四模块并行：
   - TechnicalAnalyzer 计算 MA25/99 + RSI14 + ATR14 + EMV(14,3)
   - EMVSignalGenerator 10层过滤漏斗，输出0/1信号 + filter_details
   - NewsScore 取近7天相关新闻，VADER打标（缺省=5中性，不阻塞）
   - AIClient.analyze() LLM深度分析（失败=5中性+Audit记录）
4. 综合评分 = 技术*0.4 + 新闻*0.3 + AI*0.3（0~10分）
5. score >= threshold(5.0) 才进入风控检查（连亏/日亏/仓位/重复/间隔）
6. 风控通过 -> 生成 TradeOrder -> ExchangeAdapter 下单 -> 同步TP/SL条件单
7. 写库 trade_positions / trade_orders；后续定时轮询更新浮盈亏，触发平仓更新PnL

## 3. 核心业务逻辑详解

### 3.1 标准评分引擎（strategy_type=standard）
最终得分公式：
```
final_score = tech_score * 0.4 + news_score * 0.3 + ai_score * 0.3
```
- tech_score：MA/RSI/MACD/布林带/ATR 五维加权，0-10
- news_score：VADER情感 + impact加权，0-10（无数据=5中性，不阻塞主流程）
- ai_score：LLM分析后 direction_score 映射，0-10（失败=5中性+ai_analysis_records记录）

触发条件：final_score >= score_threshold（默认5.0）

### 3.2 黄金 EMV 策略 V7（strategy_type=emv）本版本核心新增
**策略定位**：趋势跟踪 + 量价配合型；适用周期：4H；适用品种：XAU（黄金）

#### 3.2.1 V7 默认最优参数（Gap2.5% + MA斜率0.7%，25组参数中唯一正期望）
| 参数名 | 默认值 | 含义 |
|---|---|---|
| emv_period | 14 | EMV 主周期 |
| signal_period | 3 | EMV Signal 平滑周期 |
| confirm_bars | 2 | 交叉后确认K线根数 |
| emv_strength_std_mul | 0.7 | EMV强度阈值 = 滚动30根标准差 * 0.7 |
| ma99_lookback | 10 | MA99上升回看根数 |
| alignment_tol | 0.003 | 多头排列容差 |
| rsi_low / rsi_high | 38 / 68 | RSI中段过滤区间 |
| atr_vol_max_ratio | 1.5 | ATR14 / ATR120 <= 1.5x（波动率不过热） |
| breakout_pctl | 65 | 20根收盘价65分位 = 强势突破阈值 |
| ma99_slope_min_pct | 0.7 | MA99近30根涨幅 >= 0.7%（斜率加速） |
| price_above_ma99_min_pct | 2.5 | Close > MA99 * 1.025（远离纠缠区） |

#### 3.2.2 10层过滤漏斗（按顺序，任一层失败即拦截，最终通过率约3%）
1. EMV上穿Signal + 2根K线确认（交叉发生在k=i-1，k到i期间EMV均>=Signal且EMV>0）
2. MA99近10根上升（大趋势多头）
3. Close > MA25 > MA99 多头排列（MA25允许0.3%容差贴近MA99）
4. |EMV值| >= 滚动30根标准差 * 0.7（EMV强度阈值，弱信号拦截）
5. RSI14 属于 [38, 68] 中段区间（排除超买超卖假突破）
6. ATR14 / SMA(ATR14, 120) <= 1.5x（波动率不过热，极端行情拦截）
7. Close >= 过去20根收盘价的65分位（强势突破确认，弱势反弹拦截）
8. MA99近30根涨幅 >= 0.7%（长均线斜率加速，非走平阶段）
9. Close > MA99 * 1.025（远离均线纠缠区，非震荡区）
10. 滚动最近24笔历史胜率 >= 15%（观察期，连续黑天鹅拦截）

#### 3.2.3 代码入口
- 核心类：backend/strategy/emv_strategy.py -> EMVSignalGenerator.generate()
- 集成点：backend/strategy/scoring.py -> StrategyScoringEngine._compute_technical_score() EMV分支
- 前端可视化：frontend/src/views/Strategy.vue -> "信号诊断"按钮 -> 10层漏斗卡片对话框（逐层高亮true/false + 指标数值）

#### 3.2.4 V7 回测指标（6.6年 XAU/USD 4H，固定2x杠杆，弱月单笔风险0.3%/常规0.5%）
| 指标 | 值 | 评价 |
|---|---|---|
| 总交易笔数 | 18 | 样本偏少 |
| 胜率 | 33.33%（6赢12亏） | 低胜率高盈亏比模式 |
| 平均盈亏比 | 2.03 : 1 | 符合"少亏多赚"哲学 |
| 每笔期望收益 | +1.16% | 正期望（V6~V7首次转正）|
| 最大回撤 | -2.64% | 控制在3%内，很稳 |
| 参数鲁棒性 | 25组参数仅1组正期望 | 参数敏感，禁止随意修改 |

### 3.3 风控引擎逻辑（通用，所有策略共享）
#### 下单前检查（任一命中则拦截并写入ScoreRecord.reason）
- run_mode == MODE_SIMULATE -> 跳过真实下单，仅写仿真记录
- 连续亏损 >= consecutive_loss_pause（默认3笔）-> 冷却 cooldown_hours（默认24h）
- 当日已实现亏损 >= daily_max_loss%（默认5%）-> 当日剩余时间全停
- 当前持仓数 >= max_position_count（默认3个）-> 仓位达上限
- 该品种已存在同方向持仓 -> 重复开仓拦截
- 总仓位占用 >= total_position_ratio%（默认50%账户权益）-> 账户总风险超限
- 该策略最近一单开仓时间 < 品种最小开仓间隔（EMV默认3.0天）-> 交易过于频繁

#### 单笔开仓参数
- 杠杆：固定 leverage_fixed（默认3x，EMV建议2x）或动态杠杆（评分<5→3x / 5~8→5x / >=8→8x）
- 仓位大小：账户权益 * single_position_ratio%（默认10%）
- 止盈：入场价 * (1 + tp_ratio%)（默认做多+4%，EMV推荐1.8:1以上）
- 止损：入场价 * (1 - sl_ratio%)（默认做多-2%）
- 单笔最大回撤：max_single_drawdown%（默认2%，浮亏触及立即市价强平）
- Trailing Stop：EMV V7 开启（止损价随浮盈同向移动，锁定利润）

### 8.2 Fernet 加密派生规则（Exchange Key + AI Key 安全存储规范）
加密根密钥派生：
```
f = Fernet(base64.urlsafe_b64encode(hashlib.sha256(APP_SECRET_KEY.encode()).digest()))
存库：  ciphertext = f.encrypt(plaintext.encode('utf-8'))  -> bytes -> base64 string -> api_key_enc 列
读取：  f.decrypt(base64.b64decode(api_key_enc)).decode('utf-8')  -> 仅内存使用，任何API永不返回明文
```

API安全规范（已硬编码）：
- GET /exchange-accounts/{id} 返回 api_key_masked = ****abcd（只露尾4字符）
- GET /analytics/ai/config 返回 api_key_masked（同上）
- PUT 写入时，body.api_key == "__CLEAR__" -> 立即 DB 字段置 NULL
- PUT 写入时，body.api_key 非空且 != __CLEAR__ -> 视为新明文，Fernet加密后覆盖写入
- 非 admin 请求 PUT /analytics/ai/config -> 403 拦截（已在路由鉴权层）

2. 宝塔"文件"进入 `/www/wwwroot/` → 上传zip → 右键解压
3. 重命名文件夹为 `strategy-trade`（绝对路径 `/www/wwwroot/strategy-trade`）
4. 宝塔终端执行：
```bash
cd /www/wwwroot/strategy-trade
chmod +x deploy/install.sh deploy/upgrade.sh
bash deploy/install.sh
```
install.sh 会自动完成：
① 建 venv + 装 requirements.txt（可选依赖TA-Lib/ccxt缺失自动提示不阻塞）
② 复制 .env.example → .env（交互式询问 APP_SECRET_KEY / DB / Redis，全程引导）
③ 跑 backend/scripts/health_check.py 6项全绿才继续；红的提示修
④ 跑一次 python main.py 建表 + ensure_seed_data（自动创建管理员）
⑤ 写 deploy/supervisor.conf 到 /etc/supervisor/conf.d/strategy-trade.conf 并启动后端8000端口
⑥ 前端如果没有 dist 就自动 `cd frontend && npm ci && npm run build`

#### A-2 Nginx 站点配置
宝塔「网站 -> 添加站点」：域名填你的（如 trade.xxx.com），根目录选 `/www/wwwroot/strategy-trade/frontend/dist`，PHP版本选「纯静态」。
然后点「站点配置文件」，用 `deploy/nginx.conf` 的内容完全替换（里面做好了：/api 反向代理到127.0.0.1:8000；/docs和/openapi.json透传；SPA fallback index.html；gzip开；静态缓存）。

#### A-3 安装向导（WordPress式，浏览器访问根域名触发）
打开 `https://你的域名/`：
1. **Step 1 环境检测**：6项健康检查 + 目录写权限 + Python版本 + Node版本，红的必须修完才能下一步
2. **Step 2 数据库+管理员**：填MySQL连接信息（install.sh已经填好.env也可手动覆盖）+ 管理员账号密码（**覆盖默认admin/Admin@2024，不要跳过**）
3. **Step 3 完成**：自动写.env + 建表 + 种子数据 + 自动刷新Supervisor → 跳/login

也可以直接拖 `0_宝塔WordPress式一键搭建说明.htm` 到浏览器，图文版更详细。

#### A-4 升级：deploy/upgrade.sh
后续代码更新：传zip覆盖 → `bash deploy/upgrade.sh`（自动pip install新依赖 -> alembic upgrade head -> 前端build -> supervisor重启 -> health_check绿灯）

## 11. 日常运维与故障排查

### 11.1 每日巡检 Checklist（开盘前 1 分钟）
- [ ] 登录 Dashboard → 今日盈亏/总权益/持仓分布 与 交易所APP里对得上
- [ ] 查看 logs/ 最近 3 类日志 app/trade/error 的 ERROR 行（`Get-Content logs\app_最新日期.log | Select-String ERROR`）
- [ ] 交易所子账号 → 每个账号点「同步」→ 余额/持仓无异常红色告警
- [ ] 新闻页 → 昨天有新入库（<10篇 → 检查新闻Key额度或抓403；解决：填代理池或补NewsData Key）
- [ ] 风控中心 → 没有"已暂停"的策略（若有，看连亏记录决定手动解锁还是换参数）
- [ ] 健康检查脚本能过（`python backend/scripts/health_check.py`）

### 11.2 常见故障快速定位表
| 现象 | 排查步骤 | 根因 | 解决 |
|---|---|---|---|
| 前端 502 Bad Gateway | 1. supervisorctl status 后端running? 2. curl 127.0.0.1:8000/health | 后端崩了（OOM/异常未捕获）| supervisorctl restart strategy-trade；看 logs/error 日志 |
| 前端能开但请求一律401跳登录 | 1. F12 Network请求头有无Authorization 2. DevTools Application里localStorage token是否过期 | JWT过期或APP_SECRET_KEY被改过 | 重登；若改了Key所有旧token失效，用户重登即可 |
| **创建EMV策略报错 strategy_type 列不存在** | 1. SQLite：sqlite3 runtime/app.db ".schema strategy_configs" 2. MySQL：DESC strategy_configs | 老库未迁移列 | 根目录执行 py -3 migrate_emv.py 一键加列 |
| 评分时 news_score 恒=5（没新闻驱动） | 1. GET /analytics/news 近7天是否有数据 2. logs/app看NewsPipeline报错 3. Alpha Vantage额度是否25次用完 | 新闻源额度耗尽或403封IP | 补 NewsData.io Key；填 PROXY 代理池；手动 POST /analytics/news/fetch 试一次 |
| AI分析 永远返回中性5分 | 1. ai_analysis_records 最新一条 error_code 2. AI配置页 mock_enabled 是否 true | Key未配/超时/返回非JSON（已自动降级不阻塞）| 填对 Key + 选对 provider + endpoint；开启代理（OpenAI国内需代理）|
| 交易所下单报"无效API Key/IP白名单" | 1. 子账号"连通性测试"返回啥 2. Key是否勾了提币权限反而被交易所拦截 3. 测试网/实盘 is_testnet 是否搞反 4. 国内服务器是否需要代理 | Key权限/网络错 | 重建子账号Key：仅勾选"读+下单+期货"，**千万不要提币权限**；国内填代理 |
| 前端 build 报错 registerChartView is not a function | vite.config.js ElementPlusResolver importStyle 是否 sass | 按需注册echarts冲突 | 已修复：main.js 里 import * as echarts from 'echarts' 完整导入 + importStyle改为css |
| EMV评分 filter_details 缺字段/返回空 | 1. 是否删过 backend/__pycache__ 2. scoring.py EMV分支是否存在 | 缓存旧代码未加载 | Get-ChildItem -Recurse -Directory __Pycache__ | Remove-Item -Recurse -Force；重启后端 |

### 11.3 紧急止损手册（市场异常/系统BUG瞬间）
1. **暂停所有策略**：策略管理页批量停用或SQL `UPDATE strategy_configs SET status=0; COMMIT;`
2. **取消所有挂单**：每个交易所子账号点「取消所有挂单」
3. **一键全平**：当前持仓页全选 → 批量平仓（注意是市价单，流动性好的品种再用）
4. **物理级关停**：`supervisorctl stop strategy-trade`（宝塔）或直接杀后端进程；前端能看但API全部404，绝不再开新仓

## 13. 已知问题与后续开发建议

### 13.1 当前版本已知限制（交接必须知晓的风险点）
| ID | 描述 | 级别 | 建议修复版本 |
|---|---|---|---|

### 13.2 EMV策略 V8 升级方向（基于R1/R2的优化建议）
1. **双周期共振**：1H用EMV V7做方向，4H MA99斜率>=0.5%再叠加过滤 → 两周期同向才开仓，震荡假突破拦截
2. **分批止盈 Partial TP**：TP1（1%）平 50% 仓位 + 止损移保本价；TP2（2%）再平 30%；剩余 20% 放Trailing直到止损。降低胜率要求从33%降到20%即可正期望
3. **DXY美元指数过滤层**：新增 DXY(美元指数) MA25斜率；DXY走强时黄金做多胜率下降30%，DXY走弱时才放开黄金多单
4. **滚动风控样本阈值修复**：当前滚动24笔胜率<15%观察期，实盘初期样本不足容易误判；改为最少8笔交易之后观察期才生效
5. **真实数据校准 + 手续费压力测试**：从 Binance Futures Public API `GET /fapi/v1/klines?symbol=XAUUSDT&interval=4h&limit=1000` 拉取真实历史K线，叠加 0.12%（Maker+Taker双向）手续费，再重新扫25组参数，确认正期望仍然存在

### 13.3 运营/商业化建议（产品方向）
1. **策略订阅SaaS**：策略模板分三档：免费（Standard评分引擎）、Pro（EMV V7+信号诊断+DXY过滤+分批止盈，299/月）、旗舰（AI自动调参+7x24飞书告警，999/月）
2. **一键跟单社区**：管理员展示实盘/模拟盘收益曲线（带Sharpe/最大回撤指标）；用户点「Copy」→ 自动用自己的交易所子账号创建同参数策略
3. **交易所返佣分润**：对接币安/OKX 经纪商 API（经纪商ID）；引导用户通过经纪商链接开通子账号；系统按交易量自动分佣返到管理员交易所账户
4. **7x24 飞书告警**：已预对接飞书技能栈（lark-calendar/lark-task/lark-im/lark-workflow-meeting-summary）；策略评分>=8强信号/命中TP/连亏触发/日亏命中 → 飞书群机器人推送卡片 + @交易员
