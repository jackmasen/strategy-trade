## 1. 系统概述

Strategy Trade 是一套 AI 驱动的加密货币/商品量化交易系统，采用 **FastAPI + Vue 3** 前后端分离架构，集成多交易所对接（**Binance / OKX / Bybit**）、7 因子量化信号引擎、AI 行情分析、新闻情绪分析、策略自我进化、历史回测、系统监控等核心功能模块。

系统支持 **全自动 / 半自动 / 模拟盘** 三种运行模式，提供完整的「评分 → 触发 → 风控 → 下单 → 持仓管理」闭环。

## 4. 接手后新增的功能清单

### 4.1 Bybit 交易所集成 ⭐

- **文件**: `backend/exchanges/bybit.py` (BybitFuturesClient)
- **支持品种**: 加密货币(BTC/ETH/SOL) + 商品(XAU黄金/XAG白银/WTI原油) + 美股(TSLA/NVDA/AAPL/MSFT/SNDK等)
- **核心能力**:
  - USDT 永续合约交易
  - 公开行情客户端（无需 API Key）
  - MarketManager 集成：Binance 主用 + Bybit fallback
  - `get_price` 支持 REST fallback
  - `start()` 同时启动 Binance WS + Bybit WS
- **品种路由**: 加密货币走 Binance，非加密品种(股票/商品)走 Bybit
- **main.py**: 启动时自动注册 Bybit 公开客户端并订阅 9 个默认品种

### 4.2 多交易所子账号隔离 ⭐

- **策略表单新增「交易子账号」选择器**，每个策略可绑定特定交易所子账号
- 实现多账号隔离，防止不同策略间交易冲突
- 子账号选择器显示完整标签：`交易所·账号名`（如 `币安·币安AI策略交易`）

### 4.3 策略自我进化功能 ⭐

- **文件**: `backend/services/strategy_evolution.py`
- **核心能力**:
  - `apply_proposal_to_strategy()`: 真正修改策略参数（阈值/权重/TP/SL）
  - `auto_evolve()`: 自动分析 + 高置信度(≥75%)方案自动应用
  - `rollback_proposal()`: 应用前保存参数快照，支持一键回滚
  - `verify_evolution_result()`: 对比应用前后胜率验证效果
- **定时任务**: 每日 3:30 AM 自动执行进化分析
- **安全边界**:
  - 单次权重调整 ≤ 0.05（权重总和 = 1.0）
  - 阈值范围 [4.0, 7.0]
  - TP 范围 [2.0, 8.0]
  - SL 范围 [1.0, 4.0]
- **效果验证**: 应用后累计 ≥ 10 个信号对比前后胜率

### 4.4 系统监控增强

## 5. 关键技术决策与架构变更

### 5.1 强制 IPv4

```python
# main.py 第 10 行
from backend.core.force_ipv4 import *  # noqa: F401, E401
```

**原因**: 服务器有双栈 IP（IPv4: 186.244.251.11, IPv6: 2001:df1:7880:7::c），OKX API 默认走 IPv6，但用户只配了 IPv4 白名单。通过 monkey-patch urllib3 全局强制 IPv4，所有交易所 API 请求统一走 IPv4。

### 5.2 sys.path 修复

```python
# main.py 第 19-21 行
BASE_DIR = Path(__file__).resolve().parent
sys.path.insert(0, str(BASE_DIR))
```

**原因**: 宝塔 uvicorn 启动时路径问题，确保 `strategy-trade` 目录代码正确加载。

### 5.3 行情数据架构

```
MarketManager
├── Binance WS (主用: 加密货币)
├── Bybit WS (主用: 商品/股票, 加密 fallback)
├── REST fallback (缓存未命中/last_price=0 时同步获取)
└── 默认订阅: BTC/ETH/SOL/XAU/WTI/SKHYNIX/SNDK
```

- 前端定时轮询（tickerTimer / klineTimer / refreshTimer）获取聚合数据
- 缓存存在且 `last_price > 0` 时返回缓存，否则同步 REST API

### 5.4 子账号启停接口

新增 `POST /exchange/accounts/{id}/toggle-status` 专用启停接口，避免全量 PUT 更新时的字段校验问题，仅修改 `status` 字段。

### 6.4 系统内 GitHub 一键更新流程

后端 `backend/services/system_manager.py` 实现：

**检测更新** (`check_github_latest()`):
1. 读取 `.env` 中 `GITHUB_REPO` 和 `GITHUB_TOKEN`
2. 调用 `GET /repos/{repo}/releases/latest` 获取最新 Release
3. 如无 Release，回退到 `/repos/{repo}/tags` 获取最新 tag
4. 比较 `tag_name` 与当前版本（`_get_current_version()` 返回 `v1.2.7`）
5. 返回 `has_update` / `tag_name` / `zip_url` / `changelog`

**应用更新** (`apply_github_update()`):
1. 下载 Release 的 zip 包到 `.github_update/` 目录
2. 复用 `apply_update_from_upload()` 逻辑：
   - 备份当前代码
   - 解压 zip（自动提升一层嵌套目录）
   - 替换文件
   - 写入 `SystemUpdateRecord` 记录
3. 清理下载目录
4. 重启服务（Supervisor）

**版本比较** (`_compare_versions()`):
- 去除 `v` 前缀，按 `.` 分割逐段比较
- 支持语义版本号（如 v1.2.7 > v1.2.6）
