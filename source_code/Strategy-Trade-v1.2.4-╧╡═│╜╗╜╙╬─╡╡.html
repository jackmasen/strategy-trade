系统概述

Strategy Trade 是一套完整的 AI 驱动加密货币/商品量化交易系统，采用 FastAPI + Vue 3 前后端分离架构，集成多交易所对接（Binance/OKX）、7因子量化信号引擎、AI 行情分析、新闻情绪分析、策略自我进化、历史回测、系统监控等核心功能模块。系统支持全自动/半自动/模拟盘三种运行模式，提供完整的评分-触发-下单-风控闭环。

1.2 核心设计原则

  • 前后端分离：FastAPI 提供 RESTful API，Vue 3 SPA 静态资源由 FastAPI 挂载
  • 多因子量化驱动：从 3 因子（技术40%+新闻30%+AI30%）升级为 7 因子体系
  • 模拟优先：所有 AI 控制任务通过分享链接均为模拟盘（只读），无真实交易风险
  • 数据隔离：超管见全量聚合数据，运营商仅见自有数据
  • API Key 加密存储：使用 AES 加密，日志自动脱敏
  • 多 API 故障转移：AI 调用支持多 Key 轮询，失败自动切换

6. AI分析行情策略 - 详细分析

6.1 核心模块：backend/services/ai_client.py - AIClient

统一 AI 客户端，支持多供应商（OpenAI / Anthropic / DeepSeek / 通义千问 / 豆包 / 硅基流动 / OneAPI / 本地 Ollama），所有供应商走统一接口。

工作流程

  1. 前置校验：检查 API Key 和 Endpoint 是否配置
  2. 组装 Prompt：System Prompt 强制输出严格 JSON 格式（ai_score / ai_direction / ai_reason 三字段）
  3. 发请求：最多 1 次首次 + max_retries 次重试，最后一次强制 STRICT_JSON 提示
  4. JSON 解析：提取 JSON（支持 ```json 包裹和裸 JSON），字段类型/范围校验
  5. 成本估算：按模型名粗估美元成本

输出 Schema

{
  "ai_score": 0.0-10.0,         // 7-10=强烈看多, 4-6=中性, 0-3=强烈看空
  "ai_direction": "long/short/neutral",
  "ai_reason": "100-500字中文理由"
}

错误码体系

  • AI_NOT_CONFIGURED - 未配置 Key/Endpoint
  • AI_INVALID_JSON - 输出非合法 JSON（2次重试仍失败）
  • AI_PROVIDER_401 - Key 无效
  • AI_PROVIDER_429 - 限流
  • AI_TIMEOUT - 超时

6.3 7因子量化信号引擎：backend/services/quant_signal_engine.py

从"单策略触发"升级为"多因子量化信号引擎"，7大因子体系：

#因子默认权重核心指标评分范围
1市场状态 (MarketRegime)20%ADX / MA斜率 / 布林带宽 / 波动率比-10 ~ +10
2资金流向 (CapitalFlow)18%VWAP偏差 / OBV变化率 / MFI(14)-10 ~ +10
3杠杆集中度 (Leverage)15%OI变化率 / 资金费率 / 多空比-10 ~ +10
4清算压力 (Liquidation)12%上方/下方5%清算量 / 清算瀑布风险-10 ~ +10
5波动率 (Volatility)10%已实现波动率 / 波动率锥 / ATR比-10 ~ +10
6新闻情绪 (NewsSentiment)15%情绪得分 / 新闻密度 / 事件重要性 / 反身性修正-10 ~ +10
7策略优势 (StrategyAdvantage)10%各策略近期胜率 / 盈亏比 / 夏普 / 适配度-5 ~ +5

综合评分公式

CompositeScore = Σ (factor.weight * factor.confidence/100 * factor.score) / Σ (factor.weight * factor.confidence/100)

动态权重调整

  • 趋势市：market_regime 权重+5%, capital_flow 权重+2%
  • 震荡市：volatility 权重+5%, liquidation 权重+3%
  • 突破市：strategy_advantage 权重+2%

方向一致性判定

至少 60% 的有效因子（confidence > 40%）方向一致，才确认看涨/看跌信号，避免单因子偏差。

止盈止损计算

  • 止损：ATR 的 1.5 倍，范围 [1.5%, 5.0%]
  • 止盈：止损 × 盈亏比（趋势市 2.0，震荡市 1.5）
  • 建议杠杆：置信度>70 且趋势强→5x，置信度>50→3x，否则→2x

7. AI自动策略交易与回测 - 详细分析

7.1 策略引擎：backend/strategy/engine.py - StrategyEngine

评分-触发-下单闭环，由 APScheduler/Celery 定时调用。

主流程

  1. 获取K线：优先 MarketManager 内存缓存，否则通过交易所 REST 获取
  2. 评分：调用 StrategyScoringEngine 做综合评分
  3. 写入 ScoreRecord：幂等（同 strategy+symbol+tf+收盘价 不重复写）
  4. 触发交易：score_total ≥ threshold → trigger_trade=True
  5. 风控检查：日亏损限额 / 连续亏损暂停 / 最大同时持仓数
  6. 执行下单：根据 run_mode 决定是否真实下单

运行模式

模式值行为
全自动1评分达标→自动下单到交易所
半自动2评分达标→触发信号，需人工确认下单
模拟盘3评分达标→仅记录信号，不执行真实交易

杠杆策略

  • 固定杠杆：leverage_fixed (3-10)
  • 动态杠杆：按评分映射 (低→leverage_low_score, 中→leverage_mid_score, 高→leverage_high_score)

风控规则

  • max_single_drawdown: 单笔最大回撤 (默认2%)
  • daily_max_loss: 日最大亏损 (默认5%)，触发后当日停止
  • consecutive_loss_pause: 连续亏损N单暂停 (默认3单)
  • cooldown_hours: 暂停冷却时长 (默认24h)
  • max_position_count: 最大同时持仓数 (默认3)
  • total_position_ratio: 总仓位上限 (默认50%)

9. AI策略自我升级 - 详细分析

9.1 策略进化服务：backend/services/strategy_evolution.py - StrategyEvolutionService

数据驱动的策略自我进化，基于历史验证数据自动识别问题并给出优化建议。

4大核心能力

① 假信号自动识别 - analyze_false_signal_patterns()

从已验证的历史信号中挖掘失效模式，分析维度：

  • 单因子极值：某因子极端看多但结果是假信号
  • 因子矛盾：多因子方向不一致时的胜率
  • 市场状态：不同市场状态下的假信号率
  • 波动率环境：高波动/低波动下的假信号模式

输出 FalseSignalPattern：模式描述 + 严重程度 + 胜率 + 样本数

② 因子重要性分析 - analyze_factor_importance()

计算各因子对胜率的贡献度，输出 FactorPerformanceStat：

  • 各因子在"止盈"vs"止损"场景的平均得分差异
  • 因子方向准确率
  • 样本量统计（样本不足不调整，避免过拟合）

③ 参数自适应优化

根据历史表现动态调整：

  • 评分阈值（score_threshold）
  • 因子权重（weight_technical / weight_news / weight_ai）
  • 杠杆映射参数

④ 进化方案生成 - EvolutionProposal

AI 分析历史数据，给出策略优化建议：

  • 状态：pending → accepted/rejected → applied
  • 包含变更前/后参数对比
  • 预期收益改善估算
  • 可回滚（完整记录变更历史）

9.2 进化执行流程

  1. 收集历史信号数据（QuantSignalRecord，需 verified=True）
  2. 挖掘假信号模式（FalseSignalPattern）
  3. 计算因子重要性（FactorPerformanceStat）
  4. 生成进化方案（EvolutionProposal，状态=pending）
  5. 管理员审批 → accepted
  6. 应用方案 → applied，记录 EvolutionRun
  7. 如效果不佳 → 回滚到变更前参数

设计原则

  • 数据驱动：所有优化建议基于历史验证数据
  • 保守进化：样本量不足时不调整，避免过拟合
  • 可追溯：每次进化有完整记录，可回滚
