# 策略交易系统 · 本地开发与版本管理工作流（Windows 开发版）

> 目标：像做一套 **本地开发 → 存老版本 → 测新版本 → 一键打包 → 上传宝塔服务器** 的完整流水线。
> 面向角色：产品负责人 / 后端开发 / 前端开发 / 运维上线。

## 二、本地开发全流程（新建一个人，开发一个新功能）

### 2.1 新建本地虚拟环境 + 安装依赖（首次做 1 次）
> 用 **venv 隔离**（不需要 conda / 不需要 Docker Desktop 就能跑。

```powershell
# 1) 进入项目根
cd "项目根绝对路径"

# 2) 建虚拟环境（只建一次）
py -3 -m venv .venv

# 3) 激活
.\.venv\Scripts\Activate.ps1
# (cmd 激活： .\.venv\Scripts\activate.bat

# 4) 升级 pip
python -m pip install --upgrade pip
# （国内镜像，加速)
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 5) 装后端依赖
pip install -r requirements.txt
```

前端依赖：

```powershell
cd frontend
# 国内镜像加速：
npm install --registry=https://registry.npmmirror.com
# 之后日常：
cd ..
```

### 2.2 配置 `.env`（首次 1 次）
复制 `.env.example` 为 `.env`：

```powershell
Copy-Item .env.example .env
```

打开 `.env` 重点改：
- `APP_SECRET_KEY`：随便改个长字符串；
- **本地开发最简单：用 SQLite（免装 MySQL/Redis）
  - `DB_TYPE=sqlite`
  - `DB_URL=sqlite:///./runtime/app.db`
  - `REDIS_ENABLED=false`
- **要测和线上一致的 MySQL：`DB_TYPE=mysql + DB_HOST=127.0.0.1 等`
- `CORS_ORIGINS=*` 本地方便；

### 2.3 建库 + 初始化管理员（首次/切换分支后）
两种方式任选一种即可：

**方式 A：直接跑 Python 脚本（推荐）
```powershell
# 激活 venv 后
python -m backend.db.seed_data
```
> 首次自动：
- 自动 `backend/db/models.py 里所有表；
- 自动插入默认管理员（默认账号 `admin / Admin@2024`，想自定义走 `/install` 安装向导时再自定义。

**方式 B：启动后端时自动建（更省心）
```powershell
# 激活 venv 后
python main.py   # 或 uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```
首次启动会自动建库建表 + 初始化默认管理员。

### 2.4 启动后端（端口 8000）
```powershell
# 激活 venv 后
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```
验证：
- 健康检查：http://127.0.0.1:8000/health
- 接口文档：http://127.0.0.1:8000/docs
- 安装向导（未安装时自动跳）：http://127.0.0.1:8000/install

### 2.5 启动前端（端口 5173）
```powershell
cd frontend
npm run dev
```
打开：http://127.0.0.1:5173

### 2.6 开发一个功能的步骤（SOP）
1. `git checkout -b feat/xxx` 拉新分支（参考下面【版本仓库管理）；
2. 改 **后端** → 改 **前端**；
3. 浏览器走一遍完整用户路径：
   - 登录 → 仪表盘 → 策略 → 下单 → 持仓 → 历史成交 → 用户管理（管理员）
4. 跑 `py -3 local_env_diagnose.py` 扫一下语法 / 端口 / 依赖不报错；
5. 提交：**跑打包脚本** → zip 出现在桌面 → 上传宝塔 → 验证线上。

## 三、源码仓库怎么建（存老版本 + 存新版本）

### 3.1 推荐仓库结构
本地仓库根（或 Git 私有仓）建议长这样：

```
strategy-trade/                 ← 项目代码根（main.py/backend/frontend/deploy/...）
├── releases/                   ← 历史版本归档（老版本备份，随时回滚）
│   ├── v1.0.0_20250801/     ← 某次打 tag 后解压出一份
│   │   ├── README_发布说明.md
│   │   ├── 策略交易系统_onepress_v1.0.0.zip   ← 服务器用的宝塔一键包
│   │   └── 源代码快照_git_export_v1.0.0.zip   ← 代码快照
│   └── v1.1.0_20250812/
├── docs/                       ← 产品文档 / 需求 / 原型
├── .gitignore                ← 已给 git 忽略文件（见附录）
└── README.md
```

### 3.2 推荐 Git 分支命名规范（必守）
| 分支 | 用途 | 命名 | 举栗 |
| --- | --- | --- | --- |
| `main` | 线上稳定可发布（随时可打 zip 上传宝塔 |  |  |
| `develop` | 日常集成分支（开发完成，功能合进这里） |  |  |
| `feat/<功能名>` | 新功能 | 例 | `feat/add-stoploss-rule`、`feat/ai-news-summary` |
| `fix/<问题描述>` | 修 bug | 例 | `fix/trade-overview-sql`、`fix/install-wizard-env-check` |
| `release/v<主.次.修订>` | 发布分支（版本号冻结 2 周后合并回 main + tag） | 例 | `release/v1.2.0` |
| `hotfix/v<主.次.修订>` | 线上紧急修，修完直接合 main + 打 tag + 发 zip | 例 | `hotfix/v1.2.1` |
| `chore/<杂事描述> | 配置/脚本/文档类 | 例 | `chore/add-docker-compose`、`chore/update-gitignore` |

### 3.3 版本号（语义化（必守）v<MAJOR.MINOR.PATCH>
- MAJOR：大重构 / 架构变化（改数据库大字段删表）；
- MINOR：加策略 / 加页面 / 加接口 / 兼容加功能；
- PATCH：修 bug / 小优化 / 安全修复；

例子：`v1.0.0`、`v1.0.1`、`v1.1.0`、`v2.0.0`。

### 3.4 存老版本的 2 种方式
**方式 1：Git tag + 保存（推荐，最省空间）
```powershell
# 发版前
git checkout main
git tag -a v1.2.0 -m "发布 v1.2.0：新增 AI 新闻总结 + 风控止损规则优化"
git push origin v1.2.0   # 推送到远端

# 需要回滚 / 看老版本
git checkout v1.1.0        # 切到某次发布
git worktree add ../v1.1.0_check v1.1.0   # 想同时看两个版本
```

**方式 2：打 zip 放到 `releases/vX.Y.Z_日期/`（肉眼好，对非技术也能懂）
用项目里一键打包：**0_一键打包_双击我→zip自动出现在桌面.pyw`双击运行：
- 桌面得到 `策略交易系统_onepress_xxx.zip`；
- 复制进仓库 `releases/vX.Y.Z_YYYYMMDD/` 里；
- 再额外导出一份纯代码 snapshot（`git archive -o ../vX.Y.Z_src.zip HEAD）；

## 五、新版本怎么测（功能前（SOP Checklist）
每次打 tag / 合入 release 分支前，必过：
- [ ] 本地环境 `py -3 local_env_diagnose.py` 无 error；
- [ ] 全新 SQLite 模式跑一遍：登录 / 仪表盘 / 策略列表 / 新建 / 编辑 / 删除；
- [ ] 安装向导 `/install` 走一遍（首次：自定义管理员账号密码；
- [ ] 前端 `npm run build` 成功无 error（若有 error 先修）；
- [ ] 后端 `python main.py` 启动无 error；
- [ ] 健康检查 200：`/health`；
- [ ] 接口文档能打开：`/docs`；
- [ ] 前端能登录 → 操作一遍：新增策略 / 编辑 / 删除；
- [ ] （如果有接交易所 Key 则）：模拟小资金 / 模拟盘跑一圈；
- [ ] 跑打包脚本 → zip 生成到桌面 → 宝塔新站点做一个"预发布环境"先传 → 测一遍 → 再覆盖正式站点。

## 六、新版本发布 → 上传宝塔（SOP）
1. 本地：**双击桌面 `0_一键打包_双击我→zip自动出现在桌面.pyw**（或项目根同名）→ zip 出现在桌面。
2. 宝塔后台：
   - 建议先做一个 **测试站**（子域名，同服务器，和正式站分开测，比如 test.xxx.com。
3. 宝塔测试站：
   - 网站 → 添加站点 → 绑定子域名 → 根目录；
   - 文件 → 上传 zip → 解压；
   - 按 `deploy/01_部署教程` 7 步走（Nginx 反向代理 + Supervisor 守护）；
   - 访问测试站域名 → 按 WordPress 式向导走完 → 验证功能 OK。
4. 确认测试站 OK 后，**正式站升级**：
   - 正式站先备份：
     - 网站目录打一个压缩包下载到本地（代码）
     - 宝塔数据库备份一份。
   - 正式站：上传新 zip → 解压覆盖（或更推荐新目录再切根）→ 重跑 onepress-install.sh 重启后端 → 浏览器刷。
5. 正式站验证：
   - 健康 /docs / 登录 / 核心功能。
6. 新版本备份：**打 tag vX.Y.Z + releases 目录存一份。
7. 出问题 10 分钟内无法修：
   - 回滚：宝塔回滚目录 + 数据库恢复备份 → 本地 hotfix 分支修 → 再发 vX.Y.(Z+1)。

## 附录 C：常见问题快速定位
| 现象 | 排查 |
| --- | --- |
