## 2. 整体系统架构设计

### 2.1 六层分层架构

- **Layer 1 前端表现层**：Vue 3.4 + Vite 5 + Element Plus 2.7 + ECharts 5.5；15个页面；护眼深色主题；K线自定义拖拽布局（5套模板 + 用户独立存储）；EMV信号诊断10层过滤漏斗可视化
- **Layer 2 API网关层**：FastAPI 中间件链（CORS -> GZip -> 鉴权 -> 全局异常处理）；统一响应格式 {code,message,data}；JWT Bearer鉴权
- **Layer 3 业务服务层**：
  - 策略引擎 StrategyEngine（fetch_klines -> score -> risk -> order -> close 闭环）
  - 评分引擎 StrategyScoringEngine（技术40% + 新闻30% + AI30% -> 10分制）
  - EMV V7 信号生成器 EMVSignalGenerator（10层过滤漏斗）
  - 新闻AI策略 NewsStrategyService（情绪评分驱动交易信号，每小时自动执行）
  - 交易所适配层 ExchangeAdapter（Binance/OKX 统一抽象，REST+代理+测试网切换）
  - 风控引擎（TP/SL/单笔回撤/日亏/连亏/冷却/间隔）
  - 新闻流水线 NewsPipeline（并发抓取+去重+VADER情绪打标+入库）
  - 系统管理 SystemManager（健康检测/缓存清理/备份恢复/版本更新）
  - AIClient 统一封装（火山/百炼/OpenAI/本地 + Mock模式 + Audit记录）
- **Layer 4 数据访问层**：SQLAlchemy 2.0 ORM；19张主表；Alembic迁移预留
- **Layer 5 数据存储层**：MySQL 5.7+/8.0 生产强制；Redis 6+ 队列+缓存；SQLite 离线演示 fallback
- **Layer 6 外部接口层**：币安期货API / OKX API / FRED / EIA / Alpha Vantage / NewsData.io / CoinDesk RSS

## 3. 核心业务逻辑详解

### 3.1 标准评分引擎（strategy_type=standard）
最终得分公式：
```
final_score = tech_score * 0.4 + news_score * 0.3 + ai_score * 0.3
```
- tech_score：MA/RSI/MACD/布林带/ATR 五维加权，0-10
- news_score：VADER情感 + impact加权，0-10（无数据=5中性，不阻塞主流程）
- ai_score：LLM分析后 direction_score 映射，0-10（失败=5中性+Audit记录）

触发条件：final_score >= score_threshold（默认5.0）

### 3.2 黄金 EMV 策略 V7（strategy_type=emv）
**策略定位**：趋势跟踪 + 量价配合型；适用周期：4H；适用品种：XAU（黄金）

**10层过滤漏斗**（按顺序，任一层失败即拦截，最终通过率约3%）：
1. EMV上穿Signal + 2根K线确认
2. MA99近10根上升（大趋势多头）
3. Close > MA25 > MA99 多头排列
4. EMV强度阈值（滚动30根标准差 * 0.7）
5. RSI14 中段区间 [38, 68]
6. ATR波动率不过热（ATR14 / SMA(ATR14, 120) <= 1.5x）
7. 20根收盘价65分位突破
8. MA99近30根涨幅 >= 0.7%（斜率加速）
9. Close > MA99 * 1.025（远离纠缠区）
10. 滚动24笔历史胜率 >= 15%（观察期）

**回测指标**（6.6年 XAU/USD 4H，2x杠杆）：
- 胜率：33.33%（低胜率高盈亏比模式）
- 平均盈亏比：2.03:1
- 每笔期望收益：+1.16%
- 最大回撤：-2.64%

### 3.3 新闻AI策略（strategy_type=news_ai）- v1.1.0新增
- 每小时自动执行一次
- 计算24小时内相关新闻的情绪评分均值（0-100分）
- 当 abs(score-50)/5 >= threshold 时生成交易信号
- 支持杠杆倍数配置
- 写入 ScoreRecord（news分项）并发送通知

### 3.4 风控引擎逻辑
**下单前检查**（任一命中则拦截）：
- 连续亏损 >= consecutive_loss_pause（默认3笔）→ 冷却 cooldown_hours
- 当日已实现亏损 >= daily_max_loss% → 当日剩余时间全停
- 当前持仓数 >= max_position_count → 仓位达上限
- 同方向已有持仓 → 重复开仓拦截
- 总仓位占用 >= total_position_ratio% → 账户总风险超限
- 最小开仓间隔限制 → 交易过于频繁

**平仓风控**（APScheduler 每30秒巡检一次）：
- TP/SL 止盈止损（交易所条件单）
- 单笔最大回撤强平（max_single_drawdown%）
- Trailing Stop 移动止损（EMV策略）

## 6. K线自定义拖拽布局实现（v1.2.0 核心新增）

### 6.1 功能概述
K线页面支持5种布局模式，用户可自由选择和自定义：
1. **📐 经典三栏**：左盘口 + 中K线 + 右成交/持仓
2. **📊 紧凑全屏**：K线占满屏幕，信息浮动展示
3. **🎯 K线聚焦**：大K线 + 精简信息
4. **📈 仪表盘**：多面板均衡分布
5. **✨ 自定义拖拽**：用户自由拖拽调整面板位置和大小

### 6.2 技术实现
#### 6.2.1 布局系统架构
```
Kline.vue
├── layoutMode (ref)           # 当前布局模式
├── gridLayout (ref)           # 自定义布局配置（数组）
├── defaultLayout (const)      # 默认布局模板
├── allPanelsConfig (对象)     # 所有可用面板配置
├── availablePanels (computed) # 未使用的面板（可添加）
├── layoutEditMode (ref)       # 编辑模式开关
└── userStorageKey (函数)      # 按用户生成存储key
```

#### 6.2.2 面板系统
所有面板统一配置，支持拖拽和缩放：
```javascript
const allPanelsConfig = {
  'kline-main':     { w: 8, h: 12, minW: 4, minH: 6, title: 'K线主图' },
  'orderbook':      { w: 2, h: 6,  minW: 2, minH: 3, title: '深度盘口' },
  'recent-trades':  { w: 2, h: 6,  minW: 2, minH: 3, title: '近期成交' },
  'positions':      { w: 4, h: 4,  minW: 2, minH: 2, title: '当前持仓' },
  'liquidation':    { w: 2, h: 4,  minW: 2, minH: 2, title: '清算热力图' },
  'alerts':         { w: 4, h: 4,  minW: 2, minH: 2, title: '预警记录' },
  'toolbar':        { w: 12, h: 3, minW: 8, minH: 2, title: '顶部工具栏' },
  // ... 共8+个面板
}
```

#### 6.2.3 网格系统
- 12列网格布局（gridCols = 12）
- 行高 40px（gridRowHeight = 40）
- 间距 8px（gridMargin = 8）
- 每个面板配置：x, y, w, h, minW, minH

#### 6.2.4 拖拽实现
纯原生实现，无第三方依赖：
- **mousedown**：记录起始位置和面板状态
- **mousemove**：计算网格位置，实时更新面板坐标
- **mouseup**：保存最终位置，边界检查
- **边界检查**：防止拖出容器，防止面板重叠

#### 6.2.5 缩放实现
右下角缩放手柄：
- 支持宽高同时缩放
- 最小尺寸限制（minW, minH）
- 边界检查

#### 6.2.6 用户独立存储
按用户ID独立存储布局配置，避免不同用户串用：
```javascript
const userStorageKey = (key) => {
  const uid = userStore.userInfo?.id || 'guest'
  return `kline_${key}_u${uid}`
}
```

存储内容：
- `kline_layout_u{id}`：布局模式（classic/compact/focus/dashboard/custom）
- `kline_custom_layout_u{id}`：自定义拖拽布局配置（JSON）

#### 6.2.7 安全机制
1. **K线面板保护**：布局初始化时校验必须包含 kline-main 面板，否则自动恢复默认布局
2. **JSON 解析容错**：读取时 try-catch，数据损坏自动回退默认
3. **编辑模式保护**：编辑模式下才能拖拽，查看模式下锁定

#### 6.2.8 顶部工具栏（双行布局）
**第一行**：周期价格（多周期高低价横向展示）
**第二行**：品种选择 + 子账号选择 + 时间周期 + 实时价格 + 指标 + 布局切换

### 6.3 大单弹窗提醒
- 顶部居中偏左位置（不遮挡时间显示）
- 方形设计，信息清晰
- 买入绿色边框 / 卖出红色边框
- 自动消失动画
- 支持多笔同时显示

### 6.4 公开行情模式
- 子账号选择器默认「🌐 公开行情」（account_id = 0）
- 不自动选中第一个子账号，避免演示账号问题
- 用户可自主选择是否绑定子账号
- 超级管理员也能正常显示K线

## 12. 日常运维与故障排查

### 12.1 每日巡检 Checklist
- [ ] Dashboard 数据与交易所APP核对一致
- [ ] 日志无 ERROR 级别错误
- [ ] 子账号同步无异常
- [ ] 新闻正常入库
- [ ] 策略运行状态正常
- [ ] 健康检查全绿

### 12.2 常见故障快速定位
| 现象 | 根因 | 解决 |
|---|---|---|
| K线不显示数据 | 子账号问题或API Key失效 | 切换到「公开行情」模式 |
| 自定义布局保存后丢失 | 读和写的用户不一致 | v1.2.0已修复，按用户ID独立存储 |
| 超级管理员看不到K线 | 默认选中演示子账号 | v1.2.0已修复，默认公开行情 |
| 前端502 | 后端崩溃 | 重启Supervisor + 看日志 |
| 401跳登录 | JWT过期或密钥被改 | 重登即可 |
| 新闻抓不到 | 额度耗尽或403 | 补API Key + 配置代理 |
| AI分析总是中性 | Key未配或超时 | 检查AI配置 + 代理 |
| EMV filter_details缺字段 | __pycache__缓存旧代码 | 删除缓存 + 重启 |

### 12.3 紧急止损手册
1. 暂停所有策略
2. 取消所有挂单
3. 一键全平
4. 物理级关停后端进程
